Workspaces, panes, tabs

Every project gets its own room

Open a folder as a workspace with its own color, file tree and layout. Split in any direction, give each pane its own tab bar, and come back tomorrow to exactly where you left off.

  • Splits everywhere — ⌘D right, ⇧⌘D down, zoom, swap, equalize, or drag a tab onto a pane edge
  • Tab groups & vertical tabs — colored, collapsible groups; tabs in a column with agent status per row
  • Workspace groups — collapse related workspaces into one pill; color new ones by project
  • Session & scrollback restore — layouts, ratios, tab folders and colored scrollback survive a restart
  • Recipes — save a layout with commands as JSON and reopen it in one go
  • Multiple windows — tear tabs off, move workspaces, merge everything back

Multi-content tabs

A tab doesn't have to be a terminal

Browser, code editor, image viewer, markdown preview and recording player live in the same tab bars as your shells. Open the dev server next to the logs, the README next to the code.

  • Browser tabs — ⇧⌘T, or ⌘-click any URL in the terminal
  • Editor — CodeMirror with autosave, format on save, encoding and line-ending info, reload on disk change
  • Markdown & images — rendered previews, or images inline via the Kitty graphics protocol
  • Progress bars — OSC 9;4 progress shows on the tab, the workspace pill and the Dock icon

File explorer & git

Your files, even over SSH

A live file tree follows the active terminal: local folders through FSEvents, and remote shells by reusing the connection you already opened.

  • Remote browsing — SSH, Mosh, docker, podman, kubectl, lxc, lima, colima, distrobox, vagrant, adb and more
  • Git status — VS Code–style badges rolled up to folders, ignored files dimmed
  • Git sidebar — staged, unstaged and untracked files with inline stage/unstage; branch switcher in the status bar
  • Keyboard first — fuzzy filter with /, multi-select, rename, trash, type-ahead

Agents

Run Claude Code, Codex, OpenCode and more side by side

Boo tracks Claude Code, Codex, OpenCode, GitHub Copilot CLI, pi and Hermes. It knows which of your terminals run a coding agent and what each one is doing — across every window. It tells you who needs you, gives each task its own worktree, and lets you review the result before you merge.

Agent inbox

One list of every agent, summed up in the status bar and colored by state. ⇧⌘J jumps to the next agent waiting for input; a notification arrives when one finishes in a tab you're not looking at.

● needs input ● working ● done ● failed
  • Agents sidebar — open sessions, changed files with diff stats, worktrees, config and skills
  • Send to agent — ⌥⌘↩ hands the selection or last command's output to the nearest agent
  • Works remotely — agents behind ssh or mosh are tracked from their title and bell

Worktree tasks & review

File → New Agent Task… starts an agent on its own boo/<task> branch and worktree. Review the diff, comment on lines, send feedback with ⌘↩, then merge or discard.

Timeline & cost

Replay a Claude Code session: every prompt, tool call, duration, token count and cost, plus the files it edited. Repeated calls are folded so loops stand out.

Orchestrator

One Claude Code session that sees every agent (⌥⌘O). It answers waiting agents, splits work into parallel tasks and merges them — anything risky waits on an approval card.

Agents that arrange their own workspace

Boo ships an MCP server and a boo CLI. An agent can open a pane for the dev server, read the test output next door, start helpers in their own worktrees and open the review for you — and it never types into its own pane.

Terminal tools

A terminal that understands its output

Shell integration marks every prompt, so Boo knows where each command and its output start and end.

Quick select

⇧⌘Space labels every URL, path, git hash, IP and UUID on screen. Type the label to copy, with ⇧ to paste at the prompt.

Command blocks

Gutter marks per prompt (red when it failed), jump with ⌘↑/⌘↓, right-click to copy a command's output, re-run it or send it to an agent.

Copy mode

⇧⌘C puts a keyboard cursor on the scrollback. Move with vi keys, select with v/V, yank with y.

Quick terminal

⌥Space from any app drops a terminal from the top of the screen, with its own tabs that keep running while hidden.

Broadcast input

Type once into every pane of a workspace, or ⌘-click to pick panes. Panes running an agent never receive it.

History everywhere

⌃R searches every command you ran in Boo — across tabs, windows and hosts — with folder, exit code and duration.

Session recording

Record a pane. Export an MP4.

Record one pane or all of them as asciicast files — output only, never keystrokes. Drop chapter markers with ⇧⌘M, play recordings back in a tab, and render them to H.264 video in your theme and font, faster than real time.

  • Player — seek, speed from 0.25× to 4×, jump between markers
  • Idle trimming — long pauses are shortened on playback
  • Library — rename, export, reveal and trash recordings from Settings

tmux

tmux sessions as native panes

Run tmux -CC and each tmux window becomes a Boo workspace, each tmux pane a Boo pane. Focus, zoom, rename and reorder stay in sync both ways — also with other attached clients.

  • Session chip — open hidden windows, switch sessions, run any tmux command
  • Clipboard — tmux buffers land on the macOS clipboard
  • Reattach on launch — sessions attached at quit open again

Rules & profiles

Production looks like production

A profile is a set of overrides — theme, font, shader, shell, environment. A rule applies one by host, folder, container, kube context or process, or runs an action when output matches a regex.

  }]
}

Write your own

A plugin is two files of JavaScript

Drop a plugin.json and a main.js into ~/.boo/plugins/<name>/. No build step, no Node, no npm — scripts run in JavaScriptCore, and Boo reloads the plugin the moment you save.

  • Declarative UI — return stacks, labels, lists, buttons and badges from render(ctx); tints follow the theme
  • Real context — folder, git branch and changes, running process, remote host and settings arrive in ctx
  • Actions — exec, paste, cd, newTab, newPane, open, copy, notification and more
  • Hooks into Boo — status bar segments, a settings page, items in the Plugins menu with their own shortcuts
  • Scoped by when — env.local, git.active, process.name… decide where the panel appears
Plugin development guide → 
// ~/.boo/plugins/make-targets/plugin.json
{
  "id": "make-targets",
  "name": "Make Targets",
  "version": "1.0.0",
  "icon": "hammer",
  "when": "env.local",
  "runtime": "js",
  "capabilities": { "sidebarTab": true },
  "statusBar": { "position": "left", "template": "make" }
}
// ~/.boo/plugins/make-targets/main.js
function render(ctx) {
  var src = readFile("Makefile");
  if (!src) return { type: "label", text: "No Makefile", style: "muted" };

  var targets = src.split("\n")
    .map(function (l) { return (l.match(/^([a-zA-Z][\w-]*)\s*:/) || [])[1]; })
    .filter(Boolean);

  return {
    type: "list",
    items: targets.map(function (t) {
      return { label: t, icon: "terminal",
               action: { type: "exec", command: "make " + t } };
    })
  };
}

Recipes

Your whole dev setup, one click away

A recipe is a workspace you can open again: a folder plus a layout of panes, each tab starting in its own directory and running its own command. Save the current workspace as a recipe, then reopen it from the menu, the palette, the socket or MCP.

  • Plain JSON in ~/.boo/recipes/, synced with your other settings
  • Nested splits with ratios, per-tab cwd, command and env
  • Safe to save — Boo stores your last commands as hints, never runs them unasked
Recipes → 
// ~/.boo/recipes/web.json
{
  "name": "web",
  "folder": "~/code/app",
  "layout": {
    "split": "right", "ratio": 0.6,
    "a": { "tabs": [{ "command": "pnpm dev" }, {}] },
    "b": { "split": "down",
      "a": { "tabs": [{ "cwd": "./api", "command": "pnpm test --watch" }] },
      "b": {} }

FAQ

Questions, answered

How is Boo related to Ghostty?

Boo embeds Ghostty's terminal core through libghostty. Ghostty handles terminal emulation, fonts and Metal rendering; Boo builds the window, workspaces, sidebar, agent tools and everything else around it. Your Ghostty shaders and themes work in Boo.

Which coding agents does it support?

Claude Code, Codex, OpenCode, GitHub Copilot CLI, pi and Hermes are detected out of the box, including when they run behind ssh or mosh. Other AI CLIs show up in the Agents sidebar, and any agent can drive Boo through the MCP server or the boo CLI.

Do I need agents to use Boo?

No. Workspaces, splits, the file explorer, quick select, copy mode, recording, tmux integration and plugins are all useful on their own. The agent features stay out of the way until a terminal runs one.

Does it work on Intel Macs?

Release builds target macOS 15 or later on Apple Silicon. You can try building from source for other setups.

Where does Boo keep my data?

Everything lives in ~/.boo, readable only by you: settings, session, history, notes, recipes, plugins and recordings. Nothing leaves your Mac unless you turn on settings sync to a folder you pick, or remote control on your LAN.

How do updates work?

Boo updates itself through Sparkle. Releases are published on GitHub, so you can also download any version by hand.
