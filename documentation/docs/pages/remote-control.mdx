# Remote Control

Boo can serve a small web UI to control the terminal from another device on your LAN — a phone, tablet, or second computer.

## Starting the Server

**Terminal → Start Remote Control Server** starts an HTTP server (default port `8899`) and shows a URL like:

```
http://192.168.1.20:8899/#<session-token>
```

Open the URL on any device in your network. **Terminal → Copy Remote Control URL** copies it again later; selecting the menu item again stops the server.

## What You Can Do

The web UI polls the app over a JSON command API:

| Command            | Effect                                  |
| ------------------ | --------------------------------------- |
| `get_state`        | Workspaces, panes, tabs, focus          |
| `get_screen`       | Current terminal screen contents        |
| `send_text`        | Type text into the active terminal      |
| `send_key`         | Send special keys (arrows, Enter, etc.) |
| `switch_workspace` | Switch workspace                        |
| `select_pane`      | Focus a pane                            |
| `select_tab`       | Switch tab                              |
| `new_tab`          | Open a new tab                          |
| `agent_respond`    | Approve or deny a waiting agent         |
| `agent_jump`       | Bring an agent's tab to the front      |

The screen is rendered in the browser by the same terminal core Boo uses — Ghostty's VT parser compiled to WebAssembly — so colors and layout match the app.

## Answering Agents

When a coding agent waits for you (a permission prompt, see [Agent Inbox](/ipc-socket#agent-inbox)), a card appears above the screen with the agent, its workspace and the end of its screen, where the agent shows what it wants to run. The page title counts waiting agents and the phone vibrates on each new request.

- **Approve** types Return into the agent's terminal, picking the dialog's default "Yes".
- **Deny** types Escape, which cancels the request; Claude then waits for new instructions.
- **Open** brings the agent's tab to the front, so the screen below shows it.

The agent's tab does not have to be in front on the Mac. If the agent has asked something new since the card was drawn, the answer is refused instead of landing on the new question.

## Security

- Every API request must carry the session token via `Authorization: Bearer <token>`. Requests without it are rejected.
- The token is **regenerated on every server start** and delivered in the URL *fragment* (`#...`), which browsers never send over the network.
- Connections use `Connection: close`; idle connections are dropped, and client count and request sizes are bounded.

:::warning
Anyone with the URL can control your terminal. Treat the link like a password and stop the server when you're done.
:::
