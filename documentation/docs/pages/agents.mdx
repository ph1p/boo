# Agents

Boo runs coding agents (Claude Code, Codex, OpenCode) side by side. It tracks their state across all windows, gives each task its own git worktree, lets you review what they changed, and shows what a session cost.

## Agents Sidebar

The **Agents** sidebar tab covers the current workspace:

| Section        | What it shows                                                                                           |
| -------------- | ------------------------------------------------------------------------------------------------------- |
| Open Sessions  | Agent sessions. Click to focus; right-click to resume, copy the session ID, open the transcript or timeline |
| Changes        | Files changed while an agent is active, with diff stats                                                 |
| Worktrees      | The repository's worktrees. Click one to open it in a new tab                                           |
| Config, Skills | The agent's config files and skills                                                                     |

With no agent in the tab, the sidebar shows a **Start** button for each installed agent CLI.

## Agent Inbox

Boo keeps one list of agents across all windows: working, waiting for input, done or failed. A status bar segment sums it up ("Claude needs your input", "2 agents waiting"), colored by state:

| Color   | State                   |
| ------- | ----------------------- |
| Warning | Needs input             |
| Error   | Failed                  |
| Success | Done, not yet looked at |
| Accent  | Working                 |

Click the segment to list every agent and jump to it or open its timeline. **Window → Jump to Next Waiting Agent** (⇧⌘J) goes to the next agent that needs you. When an agent starts waiting or finishes in a tab you are not looking at, Boo sends a notification.

Claude Code reports through a hook. On launch, Boo adds `~/.boo/shell-integration/boo-claude-hook` to `~/.claude/settings.json` and keeps your own hooks. The file must exist, so start Claude Code once first. Agents running behind `ssh` or `mosh` are tracked from their terminal title and bell. For Codex and other agents, see [Agent Inbox](/ipc-socket#agent-inbox).

[Remote Control](/remote-control#answering-agents) can approve or deny a waiting agent from another device.

## Agent Tasks

**File → New Agent Task…** starts an agent in its own checkout, so several agents can work on one repository without clashing. Enter a task name, an optional first message and the agent. Boo creates branch `boo/<task>` in `~/.boo/worktrees/<repo>/<task>`, opens it as a workspace and starts the agent with your message.

Right-click the task's workspace:

- **Review Changes…** opens the review (below).
- **Merge Worktree…** runs `git merge --no-ff` into the branch checked out in the main repository. It refuses while there are uncommitted changes and aborts on conflicts. By default it then removes the worktree and closes the workspace.
- **Discard Worktree…** deletes the worktree and its branch, after a warning about unmerged or uncommitted work.

## Reviewing Changes

**File → Review Changes…** opens a diff tab. For an agent task it shows every commit since the branch was created, plus uncommitted and untracked files. Elsewhere it shows changes since the last commit.

Click a line to comment, add an optional overall note, then press **Send to Agent** (⌘↩). Boo pastes all comments as one numbered message into the workspace's agent and presses Return. For a task, the header also has **Merge…** and **Discard…**.

## Sending Context to an Agent

**Terminal → Send to Agent** (⌥⌘↩) pastes the selection, or else the last command's output, into the nearest agent's prompt and brings its tab to the front. It does not press Return. An agent in the same workspace wins, then the most recently active one.

Right-click a terminal for **Send Selection to …** and **Send Output of “…” to …**. Last-command output needs shell integration.

## Agent Timeline

**File → Agent Timeline**, or **Show Timeline** in the sidebar or the status bar menu, opens a tab with what a Claude Code session did: each prompt with its tool calls, duration, tokens and cost, the reply and the edited files. Calls repeated three or more times in a row are folded and highlighted, so loops stand out.

Cost is Claude Code's own figure once the session ends. While it runs, Boo estimates it from token counts and marks it with ≈.

## MCP Server

Boo is also an [MCP](https://modelcontextprotocol.io) server, so an agent inside Boo can arrange its own workspace. Register it once:

```bash
claude mcp add -s user boo -- ~/.boo/shell-integration/boo-mcp
codex mcp add boo -- ~/.boo/shell-integration/boo-mcp
```

The agent can then read the layout, open a pane for a dev server or tests, read and type into other panes, start parallel tasks and open the review for you. It never types into or closes its own pane. Tool list: [MCP Server](/ipc-socket#mcp-server).

## Orchestrator

The orchestrator is one Claude Code session that sees every window, workspace and agent. It answers waiting agents, splits work into parallel agent tasks, and reviews and merges finished tasks.

Open it with **Window → Toggle Orchestrator** (⌥⌘O) or the **Orchestrator** status bar segment. It opens in a drawer on the right edge of the front window. The drawer lists all agents (tagged **owned** when the orchestrator started them), then approval cards, then the orchestrator's terminal. Drag its left edge to resize. The session keeps running while the drawer is closed.

It needs [Claude Code](https://claude.ai/code) installed; the drawer shows the install command if it is missing. **Resume** continues the last conversation after you quit, and **New Conversation** starts over.

### Approvals

The orchestrator can read everything. It writes freely only into its own agent tasks. Anything else waits on an approval card in the drawer:

- answering an agent, or typing into an agent or a remote session (SSH, container, VM)
- closing an agent's pane
- merging or discarding a task (always, even its own)

Each card shows the action, the target and the exact text. Choose **Allow** (⌘↩), **Deny** (Esc) or **Allow for this pane** (for the rest of the session; not offered for merge or discard). If the target changes state before you decide, the card turns stale and nothing is sent. A card that arrives while the drawer is hidden triggers a notification.

If the orchestrator writes to the same agent more than three times without the agent changing state, the next write waits on a **Possible loop** card.

Before merging, it asks the agent to commit or rebase if needed. If your main checkout has uncommitted changes, it tells you and waits. It never stashes, resets or checks out anything there.
