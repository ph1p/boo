# Plugin Development

You can write a plugin in two ways:

- **JavaScript** — two files in `~/.boo/plugins/`. No build step. Boo reloads the plugin when you save. Start here.
- **Swift** — a built-in plugin compiled into Boo, with full SwiftUI and AppKit access.

[Plugin System](/plugins) explains how plugins are shown and refreshed.

## JavaScript Plugins

### Quick Start

Create a folder with a manifest and a script:

**`~/.boo/plugins/hello-world/plugin.json`**

```json
{
  "id": "hello-world",
  "name": "Hello World",
  "version": "1.0.0",
  "icon": "hand.wave",
  "runtime": "js"
}
```

**`~/.boo/plugins/hello-world/main.js`**

```javascript
function render(ctx) {
  var dir = ctx.cwd.split("/").pop();
  return {
    type: "vstack",
    children: [
      { type: "label", text: "Hello from " + dir, style: "bold" },
      { type: "button", label: "Open in Finder", action: { type: "reveal", path: ctx.cwd } },
    ],
  };
}
```

A new sidebar tab appears. External plugins always get a sidebar tab.

`render(ctx)` runs on every [plugin cycle](/plugins#how-it-works) and returns elements as an object or a JSON string. The entry function can also be named `transform`. Scripts run in JavaScriptCore inside Boo, with no Node.js and no shell.

### Manifest

| Field          | Required | Description                                                                      |
| -------------- | -------- | -------------------------------------------------------------------------------- |
| `id`           | Yes      | Unique identifier                                                                |
| `name`         | Yes      | Display name                                                                     |
| `version`      | Yes      | Version string                                                                   |
| `icon`         | Yes      | [SF Symbol](https://developer.apple.com/sf-symbols/) name                        |
| `description`  | No       | Shown in Settings → Plugins                                                      |
| `runtime`      | No       | `"js"` (the only runtime)                                                        |
| `when`         | No       | [When-clause](#when-clauses) that controls visibility. Omit to always show       |
| `capabilities` | No       | `{ "statusBarSegment": true }` adds a [status bar segment](#status-bar)          |
| `statusBar`    | No       | `position` (`"left"`/`"right"`), `priority` (lower = closer to edge), `template`, `onClick` |
| `settings`     | No       | [Settings](#settings) shown in Settings → Plugins                                |
| `menus`        | No       | [Menu items](#menu-items) in the Plugins menu                                    |

### Context

`ctx` holds the state of the focused terminal:

| Field                                | Description                                                      |
| ------------------------------------ | ---------------------------------------------------------------- |
| `cwd`, `remoteCwd`                   | Working directory; remote directory in a remote session          |
| `processName`                        | Foreground process, e.g. `"node"`                                |
| `isRemote`, `envType`, `remoteHost`  | Session type: `envType` is `"local"`, `"ssh"`, `"docker"`, `"kubectl"`, … |
| `environmentLabel`                   | Session label, e.g. `"local"`                                    |
| `terminalID`, `paneCount`, `tabCount` | Terminal UUID, panes in the workspace, tabs in the pane          |
| `git`                                | Only in a repo: `branch`, `repoRoot`, `isDirty`, `changedFileCount`, `stagedCount`, `aheadCount`, `behindCount`, `lastCommitShort` |
| `settings`                           | Your plugin's [settings](#settings)                              |
| `enrichedData`                       | Data other plugins published                                     |

### Host Functions

Paths are relative to `ctx.cwd`. Absolute paths must be inside `ctx.cwd`.

| Function           | Returns                                                          |
| ------------------ | ---------------------------------------------------------------- |
| `readFile(path)`   | File contents, or `null`                                         |
| `readJSON(path)`   | Parsed JSON, or `null`                                           |
| `fileExists(path)` | `true` / `false`                                                 |
| `listDir(path)`    | `[{ name, isDirectory }]` (max 500), or `null`                   |
| `getEnv(name)`     | Only `HOME`, `USER`, `SHELL`, `TERM`, `LANG`, `PATH`, `EDITOR`, `VISUAL`, `XDG_CONFIG_HOME` |
| `log(message)`     | Writes to Boo's log (Console.app)                                |

### Elements

| Type      | Properties                                                                                   |
| --------- | -------------------------------------------------------------------------------------------- |
| `vstack`  | `children`                                                                                   |
| `hstack`  | `children` (alias `row`)                                                                     |
| `label`   | `text`, `style` (`bold`, `muted`, `mono`), `tint`                                            |
| `button`  | `label`, `action`, `style` (`primary`, `secondary`, `destructive`), `contextMenu`            |
| `list`    | `items`: each has `label`, `detail`, `icon`, `tint`, `action`, `contextMenu`                 |
| `badge`   | `text`, `tint`                                                                               |
| `divider` | —                                                                                            |
| `spacer`  | —                                                                                            |

Tints are `success`, `error`, `warning`, `accent` and `muted`. They follow the theme. A `contextMenu` is an array of `{ label, action, icon?, style? }` and opens on right-click.

### Actions

Buttons, list items and menu entries take an `action` object:

| `type`         | Fields            | Effect                                   |
| -------------- | ----------------- | ---------------------------------------- |
| `cd`           | `path`            | `cd` in the terminal                     |
| `exec`         | `command`         | Runs the command in the terminal         |
| `paste`        | `text`            | Types text at the cursor without running it |
| `open`         | `path` (absolute) | Opens the file in its default app        |
| `reveal`       | `path`            | Shows the file in Finder                 |
| `copy`         | `text` or `path`  | Copies to the clipboard                  |
| `url`          | `url`             | Opens an `http(s)` URL in the browser    |
| `newTab`       | `path` (optional) | Opens a terminal tab                     |
| `newPane`      | `path` (optional) | Opens a split pane                       |
| `notification` | `text`, `title`   | Shows a macOS notification               |

Example: list the npm scripts of the current project.

```javascript
function render(ctx) {
  var pkg = readJSON("package.json");
  var names = pkg && pkg.scripts ? Object.keys(pkg.scripts) : [];
  if (!names.length) return { type: "label", text: "No npm scripts", style: "muted" };
  return {
    type: "list",
    items: names.map(function (name) {
      return { label: name, detail: pkg.scripts[name], icon: "play.circle",
               action: { type: "exec", command: "npm run " + name } };
    }),
  };
}
```

### Settings

Declare settings in the manifest. Boo renders the controls in **Settings → Plugins** and passes the values to `ctx.settings`.

```json
"settings": [
  { "key": "showHidden", "type": "bool", "label": "Show hidden files", "default": false },
  { "key": "limit", "type": "double", "label": "Max items", "default": 20, "min": 5, "max": 100, "step": 5 },
  { "key": "sort", "type": "string", "label": "Sort", "default": "name",
    "choices": [{ "value": "name", "label": "Name" }, { "value": "size", "label": "Size" }] }
]
```

`type` is `bool`, `string`, `int` or `double`. Optional fields:

- `description`: help text.
- `group`: a section header.
- `min`, `max`, `step`: a slider, for `double` only.
- `choices`: a picker, for `string` only.
- `options`: `"fontPicker:system"` or `"fontPicker:mono"` shows a font picker, for `string` only.

### Menu Items

Add entries to the **Plugins** menu. Handle them in `onAction(name, ctx)` and return an [action](#actions) or `null`:

```json
"menus": [
  { "label": "Run Tests", "action": "runTests", "shortcut": "shift+cmd+t", "icon": "checkmark.circle" },
  { "separator": true },
  { "label": "Open Coverage", "action": "openCoverage" }
]
```

```javascript
function onAction(name, ctx) {
  if (name === "runTests") return { type: "exec", command: "npm test" };
  if (name === "openCoverage") return { type: "open", path: ctx.cwd + "/coverage/index.html" };
  return null;
}
```

Shortcuts use the format `modifier+key`, with the modifiers `cmd`, `shift`, `ctrl` and `opt`/`alt`.

### Status Bar

Set `capabilities.statusBarSegment` to `true` to add a segment that shows the plugin icon and text. The text is `statusBar.template` or, without a template, the plugin name. Clicking the segment opens the plugin's tab.

```json
"capabilities": { "statusBarSegment": true },
"statusBar": { "position": "left", "priority": 45, "template": "{git.branch} ({git.changedCount})" }
```

Template tokens: `{cwd}`, `{process.name}`, `{git.branch}`, `{git.changedCount}`, `{remote.host}`.

### When-Clauses

`when` hides the plugin unless the expression is true. For example, `"git.active && !remote"`.

| Kind             | Variables                                                                                     |
| ---------------- | --------------------------------------------------------------------------------------------- |
| Boolean          | `remote`, `env.local`, `env.ssh` (SSH or Mosh), `env.mosh`, `env.docker`, `env.container`, `git.active`, `git.dirty`, `process.running`, `process.editor`, `process.vcs`, `process.ai` |
| String (`==`/`!=`) | `env.type`, `remote.host`, `process.name`, `process.category`, `git.branch`, `cwd`          |

Operators: `!`, `&&`, `||`, `==`, `!=` and `( )`. Quote strings with single quotes: `"env.type == 'kubectl'"`. The process categories are in `Boo/Services/ProcessIcon.swift`.

### Debugging

- If `render` throws, the tab shows the error. If it runs longer than 1 second, the tab shows a timeout.
- `onAction` also has a 1-second limit.
- Use `log()` and watch Console.app.

### Examples

[`examples/plugins/`](https://github.com/ph1p/boo/tree/main/examples/plugins) holds working plugins. Start with `hello-world` and `make-targets`. `node-project` and `terminal-inspector` use every element, action and context field.

## Swift Plugins

A built-in plugin is a class that conforms to `BooPluginProtocol` (`Boo/Plugin/BooPluginProtocol.swift`). Every method has a default, so you implement only what you need. Put it in `Boo/Plugins/<Name>/`. Put its tests in `Tests/BooTests/Plugins/<Name>/`.

### Minimal Plugin

```swift
import SwiftUI

@MainActor
final class HelloPlugin: BooPluginProtocol {
    // Required: the host injects these.
    var actions: PluginActions?
    var services: PluginServices?
    var hostActions: PluginHostActions?
    var onRequestCycleRerun: (() -> Void)?
    var subscribedEvents: Set<PluginEvent> { [] }

    let manifest = PluginManifest(
        id: "hello",
        name: "Hello",
        version: "1.0.0",
        icon: "hand.wave",
        description: "Shows the current directory",
        when: "!remote",
        runtime: nil,
        capabilities: PluginManifest.Capabilities(statusBarSegment: false, sidebarTab: true),
        statusBar: nil,
        settings: nil
    )

    func makeDetailView(context: PluginContext) -> AnyView? {
        let t = Tokens.current
        let scale = context.fontScale
        return AnyView(
            VStack(alignment: .leading, spacing: 4) {
                Text((context.terminal.cwd as NSString).lastPathComponent)
                    .font(scale.font(.base).weight(.semibold))
                    .foregroundStyle(t.text)
                Text(context.terminal.cwd)
                    .font(scale.font(.sm, design: .monospaced))
                    .foregroundStyle(t.muted)
                Button("List files") { self.actions?.exec("ls -la") }
            }
            .padding(8)
        )
    }
}
```

Register it in `PluginRegistry.registerBuiltins()` (`Boo/Plugin/PluginRegistry.swift`):

```swift
register(HelloPlugin())
```

`Boo/Plugins/Notes/NotesPlugin.swift` and `Boo/Plugins/SystemInfo/SystemInfoPlugin.swift` are short real plugins to copy from.

### Lifecycle

- **Events.** `subscribedEvents` lists the callbacks your plugin receives: `.cwdChanged`, `.processChanged`, `.remoteSessionChanged`, `.focusChanged`, `.terminalCreated`, `.terminalClosed`, `.remoteDirectoryListed`, `.commandStarted` and `.commandEnded`. Each event has a matching method, such as `cwdChanged(newPath:context:)` or `commandEnded(result:context:)`. Boo skips events you do not subscribe to.
- **Every cycle.** `enrich(context:)` publishes shared data with `context.setData(_:forKey:)`. Prefix keys with your plugin ID. `react(context:)` reads the frozen `TerminalContext`, including `enrichedData`. Both must be fast, under 2 ms each.
- **Activation.** `pluginDidActivate()` and `pluginDidDeactivate()` run when your tab is selected or deselected. Start and stop timers and watchers there.
- **Background data.** Call `onRequestCycleRerun?()` on the main thread to rebuild the sidebar and status bar.
- **Availability.** Return `false` from `checkAvailability() async` to hide the plugin, for example when a required binary is missing.

```swift
var subscribedEvents: Set<PluginEvent> { [.cwdChanged] }

func cwdChanged(newPath: String, context: TerminalContext) {
    if FileManager.default.fileExists(atPath: newPath + "/.envrc") {
        actions?.exec("direnv allow .")
    }
}
```

### Sidebar Sections

With `sidebarTab: true`, the default `makeSidebarTab(context:)` puts `makeDetailView` in a single section. Override these to change the section:

- `sectionTitle(context:)`: a dynamic header. Return `nil` to use `manifest.name`.
- `prefersOuterScrollView`: return `false` if your view scrolls itself.
- `sectionGeneration(context:)`: by default the view is rebuilt every cycle. To reuse it, return `SidebarSection.generation(for: [keys])` over the values your view depends on.
- `sectionIdentity(context:)`: return a new value to reset the view's `@State`, for example on a workspace switch.

For several collapsible sections, override `makeSidebarTab(context:)` and return a `SidebarTab` with more than one `SidebarSection`.

### Theme and Fonts

- **Colors.** Use the semantic tokens from `Tokens.current` in sidebar views, such as `t.text`, `t.muted`, `t.textSecondary`, `t.accent`, `t.success`, `t.error` and `t.hoverFill`. Views opened in a content tab get the same tokens through `@Environment(\.tokens)`. [Theming](/theming#derived-semantic-tokens) lists every token.
- **Fonts.** `context.fontScale.font(.xs | .sm | .base | .lg | .xl)` follows the sidebar font setting. Do not hardcode point sizes.

### Settings

Declare settings in the manifest and read them through `context.settings`:

```swift
settings: [
    PluginManifest.SettingManifest(
        key: "greeting", type: .string, label: "Greeting",
        defaultValue: AnyCodableValue("Hello"), options: nil)
]

let greeting = context.settings.string("greeting", default: "Hello")
```

### Status Bar and Menus

- **Status bar.** Set `statusBarSegment: true` and `statusBar: PluginManifest.StatusBarManifest(position: "right", priority: 25, template: nil)`. Then return a `StatusBarContent(text:icon:tint:accessibilityLabel:)` from `makeStatusBarContent(context:)`.
- **Menus.** Declare `menus` in the manifest and handle them in `handleMenuAction(_:context:)`.

### Actions

`actions` (`Boo/Plugin/PluginActions.swift`) sends work to the terminal and the app:

- Terminal: `exec`, `cd(to:)`, `pastePath`.
- Clipboard and Finder: `copy`, `reveal`, `openInEditor`.
- Tabs and panes: `openDirectoryInNewTab`, `openDirectoryInNewPane`, `openFile`, `openTab`, `registerMultiContentTab` and `openMultiContentTab`.
