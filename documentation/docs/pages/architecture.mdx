# Architecture

## Stack

- **Swift** on macOS 15+. **AppKit** for the window and terminals, **SwiftUI** for the sidebar and settings.
- **GhosttyKit**: terminal emulation with Metal rendering, through its C API. See [Ghostty Integration](/ghostty-integration).
- **PTY**: owned by Ghostty. Each `GhosttyView` surface spawns and drives its own shell.
- **Monaco** in a `WKWebView` for the editor. See [Multi-Content Tabs](/multi-content-tabs#editor).

Build commands are in [Contributing](/contributing).

A plugin keeps all its files in one folder under `Boo/Plugins/`. Tests mirror this under `Tests/BooTests/Plugins/`.

## Hierarchy

```
WindowManager → MainWindowController[] → Workspace[] → SplitTree → Pane[] → Tab[] → TabState
```

Each split pane has its own tab bar. Each window has its own workspaces, sidebar and plugin registry. Settings, themes and bookmarks are global.

## State Model

| Scope      | Type                     | Holds |
| ---------- | ------------------------ | ----- |
| Global     | `AppSettings.shared`     | Theme, font, layout, status bar, plugin settings. Posts `.settingsChanged`. |
| Per tab    | `TabState`               | Everything about one tab (below) |
| SwiftUI    | `AppStore.shared`        | Current `TerminalContext`, theme snapshot, sidebar visibility. Updated after each plugin cycle. |

`TabState` (in `Models/Pane.swift`) is the source of truth for a tab:

- **Content**: `contentType`, `contentState`
- **Terminal**: `workingDirectory`, `remoteSession`, `remoteWorkingDirectory`, `shellPID`, `title`
- **Process**: `foregroundProcess` with its PID, category and metadata; `agentSessionID`
- **Status**: `hasActivity`, `isCommandRunning`, `progress` (OSC 9;4), `isRecording`, `triggerMark`
- **Profile**: `profile`, `profileOverride` (see [Rules and Profiles](/rules-and-profiles))
- **Sidebar UI**: expanded plugins, collapsed sections, section heights, scroll offsets, section order, selected plugin tab

When you add state, decide first: is it global (`AppSettings`) or per tab (`TabState`)?

## Data Flow

```
Ghostty action → GhosttyView → PaneView delegate → MainWindowController
  → TerminalBridge (heuristics, remote detection)
  → WindowStateCoordinator.syncBridgeToTab() → TabState
  → runPluginCycle(reason:) → TerminalContext (frozen snapshot)
  → PluginRuntime (enrich → freeze → react) → sidebar and status bar
```

| Component                  | Job |
| -------------------------- | --- |
| **WindowManager**          | Owns all windows, routes app-wide commands, saves the session |
| **MainWindowController**   | Window lifecycle, menu actions, high-level coordination |
| **WindowStateCoordinator** | Syncs bridge ↔ tab, saves and restores plugin state |
| **TerminalBridge**         | Parses events, runs heuristics, detects remote sessions. Its `BridgeState` is live but transient. |
| **SidebarController**      | Panel visibility, tab selection, heights |

## Command Routing

The socket, Remote Control and MCP all go through `WindowManager.dispatchCommand`:

1. Agent commands (`agent_event`, `agent_inbox`, `agent_respond`, `agent_jump`, `agent_timeline`) and `wait_for_events` go to the app-wide agent services.
2. Commands addressed by `tab_id` (`get_screen`, task commands) and `get_layout` with `scope: "app"` find their tab in any window.
3. A command with `pane_id` goes to the window that owns the pane.
4. Anything else goes to the active window.

Before that, `dispatchGated` checks [capability tokens](/ipc-socket#capability-tokens) for sensitive commands. See [IPC Socket](/ipc-socket).

## State Contracts

| Data                  | Source of truth        | Saved in                           | Sync |
| --------------------- | ---------------------- | ---------------------------------- | ---- |
| Working directory     | BridgeState (live)     | TabState                           | On tab switch |
| Remote session        | BridgeState (live)     | Not saved                          | Re-detected on restore from the process tree |
| Remote CWD            | BridgeState (live)     | TabState                           | On tab switch |
| Foreground process    | BridgeState (live)     | TabState                           | On tab switch |
| Terminal title        | BridgeState (live)     | TabState                           | On tab switch |
| Shell PID             | TabState               | SessionStore                       | Set once when the terminal starts |
| Agent session ID      | TabState               | SessionStore                       | Set by plugin detection |
| Expanded plugins      | WindowStateCoordinator | TabState                           | On tab switch |
| Active plugin tab     | WindowStateCoordinator | TabState                           | On tab switch |
| Section heights       | SidebarPanelView       | TabState + `AppSettings.__sidebar` | On tab switch and quit |
| Section order         | WindowStateCoordinator | `AppSettings.__sidebar`            | On reorder and quit |
| Scroll offsets        | SidebarPanelView       | TabState                           | On tab switch |
| Theme                 | AppSettings            | UserDefaults + `~/.boo/settings.json` | At once |
| Sidebar visible       | MainWindowController   | Not saved                          | Runtime only |

`SidebarPanelView` lives in `Views/DetailPanelView.swift`.

### Rules

1. Sync `BridgeState` to `TabState` with `syncBridgeToTab()` before every tab switch.
2. Never save the remote session. It is always re-detected.
3. Plugin settings live under `pluginSettings[pluginID][key]`.
4. Every `AppSettings` change posts `.settingsChanged`.

### Tab Switch

1. `syncBridgeToTab(pane:tabIndex:)` saves bridge → old tab.
2. `savePluginState(to:tabIndex:)` saves plugin UI → old tab.
3. `restorePluginState(from:)` restores plugin UI ← new tab.
4. `TerminalBridge.restoreTabState` restores bridge ← new tab.

### App Quit

`WindowManager.saveSessionForTermination()`:

1. For each window, `saveSidebarStateToSettings()` writes heights, order and global sidebar state to `AppSettings.__sidebar`. `prepareSessionSave()` writes pane content, sidebar and plugin state into the model.
2. `SessionStore` saves one `SessionSnapshot` with a `SessionWindow` per window and the `keyWindowIndex`.
