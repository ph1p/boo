# IPC Socket

Boo listens on a Unix socket at `~/.boo/boo.sock`. Scripts, plugins and agents use it to read and drive the app.

Every Boo terminal sets these variables:

| Variable      | Value                                         |
| ------------- | --------------------------------------------- |
| `BOO_SOCK`    | Socket path                                   |
| `BOO_TERM`    | `1`                                           |
| `BOO_PANE_ID` | ID of this pane                               |
| `BOO_TAB_ID`  | ID of this tab                                |
| `BOO_TOKEN`   | [Capability token](#capability-tokens) of this terminal |

## Protocol

Newline-delimited JSON: one request per line, one reply per request. A failed command replies `ok: false` with an `error`. A connection that sends `subscribe` stays open and receives [events](#event-subscriptions) as `{"event": name, "data": {…}}`.

```bash
echo '{"cmd":"get_context"}' | nc -U "$BOO_SOCK"
```

## Routing

Most commands act on the frontmost Boo window. With a `pane_id` they go to the window that holds that pane. Commands with a `tab_id` (agents, tasks, `get_screen`) find the tab in any window.

| ------------------ | --------- | ----- |

| `list_themes`      | | `themes` (names) |
| `switch_workspace` | `index` or `id` | |
| `new_tab`          | optional `cwd` (default: workspace folder), `command`, `env` (strings; `BOO_*` keys are ignored). Opens in the active pane. | `tab_id` |
| `new_workspace`    | optional `path` (default: home) | |
| `new_window`       | | `windows` (count) |

| `select_tab`       | `index` of a tab in the active pane | |

| `list_recipes`     | | `recipes` (`name`, `path`, `folder`; `folder` is null when the file is invalid) |

## `send_text` and `get_screen`

`send_text` writes `text` to a terminal, as if typed.

- Without `pane_id`, it goes to the active terminal.
- With `pane_id`, it goes to that pane, in any workspace of its window.
- With `submit: true`, the text is pasted as one input and Return is pressed. Use this to send a prompt to an agent.

`get_screen` reads a terminal and returns `text`, `title` and `cwd`.

| Arguments                 | Returns |
| ------------------------- | ------- |
| none                      | Visible screen of the active pane, plus `cols`, `rows` and a styled `vt` snapshot |
| `pane_id`                 | Visible screen of that pane |
| `tab_id`                  | Visible screen of that tab, in any window |
| `lines` (max 5000)        | The last `lines` of output, scrollback included. Combines with `pane_id` or `tab_id`. |

```bash
echo '{"cmd":"send_text","text":"cd ~/projects/myapp\n"}' | nc -U "$BOO_SOCK"
echo '{"cmd":"send_text","pane_id":"<id>","text":"pnpm test","submit":true}' | nc -U "$BOO_SOCK"
echo '{"cmd":"get_screen","pane_id":"<id>","lines":50}' | nc -U "$BOO_SOCK"
```

## Pane Layout

Pane commands act on the active workspace of the frontmost window. `direction` is `left`, `right`, `up` or `down`.

- `split_pane`, `close_pane` and `get_layout` also accept a `pane_id` in a background workspace.
- `focus_pane`, `resize_pane`, `swap_pane`, `zoom_pane` and `equalize_splits` need the pane on screen. Otherwise they fail with `pane is in a background workspace; switch to it first`.

| Command                        | Arguments | Reply |
| ------------------------------ | --------- | ----- |
| `split_pane`                   | `direction` (default `right`), `pane_id` to split (default active), `command`, `cwd`, `focus` (default `true`) | `pane_id`, `started` |
| `close_pane`                   | `pane_id` (default active). Never closes the only pane. | `active_pane` |
| `focus_pane`                   | `direction`, `next` or `previous`. `pane_id` alone focuses that pane; with `direction` it moves from there. | `active_pane` |
| `resize_pane`                  | `direction`, `amount` in points (default 10), `pane_id` | |
| `swap_pane`                    | `direction`, `pane_id` | |
| `zoom_pane`                    | `zoomed` (`true`/`false`, omit to toggle), `pane_id` | `zoomed` |
| `equalize_splits`              | optional `pane_id` | |
| `get_layout`                   | `pane_id` for that pane's workspace; `scope: "app"` for every window | `tree`, `panes`, `windows`, `workspace_visible` |
| `move_workspace_to_new_window` | `index` (default active) | `windows` |
| `merge_all_windows`            | Moves every window's workspaces into the active one | `workspaces` |

`get_layout` returns the split tree with ratios. Each pane has:

- `frame`: on-screen position in points, top-left origin. Left out for a background workspace.
- `visible`: false while another pane is zoomed.
- `grid`: terminal columns and rows.
- `tabs`: `id`, `title`, `type`, `active`, `cwd`, `process`.

A pane split into a background workspace replies `started: false`. Its shell and `command` start when the workspace is next shown.

```bash
echo '{"cmd":"split_pane","direction":"down"}' | nc -U "$BOO_SOCK"
echo '{"cmd":"get_layout"}' | nc -U "$BOO_SOCK"
```

## Event Subscriptions

Send `subscribe` with a list of `events` and keep the connection open. `"events": ["*"]` subscribes to all.

| Event                    | Data |
| ------------------------ | ---- |
| `cwd_changed`            | `path`, `is_remote`, `pane_id` |
| `title_changed`          | `title`, `pane_id` |
| `process_changed`        | `name`, `category`, `pane_id`, `pid`, `metadata` |
| `remote_session_changed` | `type`, `host`, `active`, `pane_id` |
| `focus_changed`          | `pane_id` |
| `workspace_switched`     | `workspace_id` |
| `theme_changed`          | `name`, `is_dark` |
| `settings_changed`       | `topic` |
| `cmd_started`            | `command`, `pane_id` |
| `cmd_ended`              | `command`, `exit_code`, `duration`, `pane_id` |

### Reacting to Directory Changes

Subscribe to `cwd_changed`, then act with another command. This script lists each new directory in the same pane:

```bash
echo '{"cmd":"subscribe","events":["cwd_changed"]}' | nc -U "$BOO_SOCK" | while read -r line; do
  pane=$(echo "$line" | jq -r '.data.pane_id // empty')
  [ -n "$pane" ] && echo '{"cmd":"send_text","pane_id":"'"$pane"'","text":"ls\n"}' | nc -U "$BOO_SOCK"
done
```

## Agent Inbox

The inbox is Boo's list of coding agents across all windows. See [Agents](/agents#agent-inbox) for the UI.

Claude Code reports through a hook that Boo installs. For Codex, add to `~/.codex/config.toml`:

```toml
notify = ["~/.boo/shell-integration/boo-claude-hook", "codex"]
```

Other agents report with `agent_event`:

| Command         | Arguments | Reply |
| --------------- | --------- | ----- |
| `agent_event`   | `event`; `tab_id` or `pane_id` (`$BOO_TAB_ID` / `$BOO_PANE_ID`); optional `agent`, `message`, `tool`, `session_id`, `cwd` | `state` |
| `agent_inbox`   | | `attention`, `items` |
| `agent_jump`    | `tab_id`, or none for the next waiting agent | |
| `agent_respond` | `tab_id` and either `response` or `text` (see below) | |

`event` is one of `working`, `needs-input`, `done`, `error` or `end`. Aliases: `prompt`, `tool` and `working` mean working; `permission` and `question` mean needs-input; `stop` means done.

- `needs-input` lasts until the agent works again.
- `done` and `error` last until you look at the tab.
- Both send a notification unless the tab is in front.
- `end` removes the agent from the list.

`agent_respond` answers an agent:

- `response: "approve"` types Return; `"deny"` types Escape. The agent must be in needs-input. Pass `updated_at` from `agent_inbox` to refuse when the agent asked something newer.
- `text` sends a message to the agent. This fails while the agent is in needs-input.

```bash
echo '{"cmd":"agent_event","pane_id":"'"$BOO_PANE_ID"'","event":"needs-input","agent":"aider","message":"Apply edits?"}' | nc -U "$BOO_SOCK"
```

### Waiting for Events

`wait_for_events` blocks until something happens: an agent changes state, a task starts or ends, a pane closes or an approval resolves.

- `since`: the `seq` from the last reply. Events after it return at once.
- `timeout`: seconds (default 300, max 540). On timeout the reply has no events.

Reply: `seq`, `events`, and `missed: true` when older events were dropped.

## Agent Timeline

`agent_timeline` returns what a Claude Code session did, read from its transcript in `~/.claude/projects` (or `$CLAUDE_CONFIG_DIR`). See [Agents](/agents#agent-timeline) for the tab.

| Arguments | Reply |
| --------- | ----- |
| `tab_id` (an inbox agent) or `session_id`; optional `turns` (default 10), `open: true` to show the tab | `cost`, `cost_exact`, `tokens`, `prompts`, `tool_calls`, `loops`, `files`, last `turns` |

`cost_exact` is false while the session runs. Boo then estimates cost from token counts.

## Agent Tasks

An agent task is a git worktree on branch `boo/<task>` in `~/.boo/worktrees/<repo>/<task>`. See [Agents](/agents#agent-tasks).

| Command          | Arguments | Reply |
| ---------------- | --------- | ----- |
| `new_agent_task` | `name` and/or `prompt`; optional `agent` (`claude`, `codex`, `opencode`), `model`, `repo` (default: active terminal's repo, else workspace), `base` (ref to branch from) | `path`, `workspace_id` |
| `review_changes` | optional `workspace_id` or `pane_id` (default: active workspace) | |
| `task_status`    | `tab_id` of the task's agent | `branch`, `target`, `ahead`, `behind`, `dirty`, `target_dirty`, `conflicts`, `mergeable`, `blocker`, `hint` |
| `task_diff`      | `tab_id`; `stat_only: true` for the file list only | `base`, `files`, `additions`, `deletions`, `diff` (max 100,000 chars), `truncated` |
| `merge_task`     | `tab_id`; `cleanup` (default `true`) removes the worktree and closes the workspace | `merged`, `target`, or `error` and `blocker` |
| `discard_task`   | `tab_id` | |

`blocker` is one of `no_target`, `dirty`, `target_dirty`, `conflicts` or `nothing_to_merge`. `hint` says what to do about it.

```bash
echo '{"cmd":"new_agent_task","name":"fix login","prompt":"The login redirect loops, fix it"}' | nc -U "$BOO_SOCK"
```

### Handing context to an agent

**Terminal → Send to Agent** (⌥⌘↩) pastes the selection, or the last command's output, into the nearest agent. See [Agents](/agents#sending-context-to-an-agent). From a script, use `send_text` with the agent's `pane_id`.

## MCP Server

`Boo --mcp` is an [MCP](https://modelcontextprotocol.io) server over stdio. The installed app writes a launcher to `~/.boo/shell-integration/boo-mcp` on every start. Register it once:

```bash
claude mcp add -s user boo -- ~/.boo/shell-integration/boo-mcp
codex mcp add boo -- ~/.boo/shell-integration/boo-mcp
```

The server talks to the running app over `$BOO_SOCK`. It uses `$BOO_PANE_ID` as the agent's own pane and sends `$BOO_TOKEN` for you. It never types into or closes the agent's own pane.

| Tool              | What it does |
| ----------------- | ------------ |
| `get_layout`      | Panes of the agent's workspace with tabs, cwd and process. `your_pane` is the agent's own. |
| `split_pane`      | New pane beside the agent's (`direction`, `command`, `cwd`, `pane_id`). Focus stays unless `focus`. |
| `read_pane`       | Last `lines` (default 100) of a pane's output |
| `send_text`       | Type into another pane. Presses Return unless `submit` is false. |
| `close_pane`      | Close another pane |
| `list_agents`     | The agent inbox |
| `new_agent_task`  | Worktree task on the agent's repository with a first `prompt` |
| `run_recipe`      | Open a [recipe](/features#recipes) by `name` |
| `open_review`     | Review tab for the agent's workspace |
| `wait_for_events` | Block until something happens (`since`, `timeout`) |
| `agent_respond`   | Approve, deny or answer a waiting agent by `tab_id` |
| `focus_pane`      | Bring an agent's tab to the front |
| `task_status`     | A task's commits, changes, conflicts and merge blocker |
| `task_diff`       | A task's changes (`stat_only` for the summary) |
| `merge_task`      | Merge a task into its main checkout (`cleanup` removes the worktree) |
| `discard_task`    | Delete a task's worktree and branch |

## Status Bar Segments

Processes can add their own status bar segments. They are removed when the connection closes.

```bash
echo '{"cmd":"statusbar.set","id":"ci","text":"CI: passing","icon":"checkmark.circle","tint":"green"}' \
  | nc -U "$BOO_SOCK"
```

`tint` is `red`, `green`, `yellow`, `blue`, `orange`, `purple`, `accent` or a `#rrggbb` hex color.

To mark a process as an agent or tool, use `set_status`:

```bash
echo '{"cmd":"set_status","pid":'"$$"',"name":"claude","category":"ai"}' | nc -U "$BOO_SOCK"
```

## Security

- The socket only accepts processes of the same user (`LOCAL_PEERCRED`).
- Socket I/O runs on one serial queue.
- A PID registered with `set_status` only counts for a tab whose shell it descends from.
- Dead processes and closed connections are cleaned up.

### Capability tokens

Every Boo terminal gets a random `BOO_TOKEN`. A command needs it when it gives a process power it lacks in its own shell:

- `agent_respond`
- `send_text` or `send_key` into an agent or a remote session
- `close_pane` on an agent pane
- `merge_task` and `discard_task`

Send the token as `"token"` in the request.

- A normal terminal's token runs these commands directly.
- The [orchestrator](/agents#orchestrator)'s token puts them on an approval card, except writes to agents it started. Merge and discard always need a card. The reply is `{"status":"pending","approval_id":…}`.
- Without a token, these commands are rejected. All other commands work without one.

Tokens live in memory and change when Boo restarts. They stop mistakes and model overreach. They do not stop an attacker running as the same user, who can read another process's environment.
