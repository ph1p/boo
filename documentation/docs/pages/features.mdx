# Features

## Command Palette

**Cmd+Shift+P** opens a search over every menu command (plugin commands included), the workspaces and tabs of all windows, bookmarks, SSH hosts, themes, profiles and [recipes](#recipes). Matching is fuzzy, and recent picks rank higher. Each command shows its shortcut; commands that can't run right now are dimmed.

- **Prefixes** — `>` commands, `@` workspaces, `@ssh` SSH hosts, `#` tabs, `:` themes and [profiles](/rules-and-profiles#profiles), `!` [command history](/history-and-sync#shell-history)
- **Theme preview** — Highlighting a theme previews it live; **Esc** reverts
- **Keys** — **Up**/**Down** move, **Return** runs, **Esc** closes

## Workspaces

Open folders as workspaces with their own file tree using **Cmd+Shift+N** (home directory) or **Cmd+Shift+O** (choose folder). Each workspace maintains its own state, color, and name.

- **Workspace colors** — Assign preset or custom colors per workspace
- **Pinning** — Pin frequently used workspaces
- **Color by project** — With **Settings → Layout → Color new workspaces by project**, each new workspace gets a color derived from its repository (or folder). The same project gets the same color every time; a color you pick wins.
- **Renaming** — Double-click a workspace pill to rename it, or use the right-click context menu
- **Session persistence** — Workspace names, colors, split layouts, tab paths, and split pane ratios are saved to `~/.boo/session.json` and restored on next launch. Remote connections are not restored; tabs reopen at their local working directory.
- **Scrollback restore** — On quit, each terminal's screen and scrollback (up to 2 MB per tab, colors included) is saved to `~/.boo/scrollback/` and replayed into the tab on next launch. The files are owner-only and deleted once replayed. Turn it off under Settings → General → Startup.
- **Drag to switch workspace** — While dragging a tab, hover over a workspace pill for ~500 ms to spring-load into that workspace, then drop the tab onto any pane there.

## Recipes

A recipe is a workspace you can open again: a folder plus a layout of panes, each with tabs that start in a given directory and can run a command. Recipes are JSON files in `~/.boo/recipes/`; open one from **File → Recipes**, the command palette, or `run_recipe` over the socket and MCP.

```json
{
  "name": "web",
  "folder": "~/code/app",
  "layout": {
    "split": "right", "ratio": 0.6,
    "a": { "tabs": [{ "command": "pnpm dev" }, {}] },
    "b": { "split": "down",
           "a": { "tabs": [{ "cwd": "./api", "command": "pnpm test --watch", "env": { "PORT": "4000" } }] },
           "b": {} } }
}
```

A node is either a pane (`tabs`, empty for one plain shell) or a split: `"right"` puts `a` left of `b`, `"down"` puts it above, and `ratio` (default 0.5) is `a`'s share. A tab's `cwd` is absolute, `~/…`, or relative to `folder`. **File → Recipes → Save Workspace as Recipe…** writes the current layout and tab folders. It never stores commands to run: each tab's last command is kept as `lastCommand`, so copy it into `command` if the tab should run it. A recipe whose folder no longer exists opens nothing and says why.

## Split Panes

Split your terminal in any direction:

- **Cmd+D** — Split right
- **Cmd+Shift+D** — Split down
- **Cmd+]** / **Cmd+[** — Focus next / previous pane
- **Cmd+Opt+Arrows** — Select the pane in that direction
- **Cmd+Ctrl+Arrows** / **Cmd+Ctrl+Shift+Arrows** — Resize / swap panes
- **Cmd+Shift+Return** — Zoom the active pane; **Cmd+Ctrl+=** — equalize splits

Each split pane is independent with its own tab bar and terminal sessions. Drag the divider between panes to resize, or drag a tab onto a pane edge to split; ratios are saved and restored across launches.

### Broadcast Input

**Terminal → Broadcast Input to → All Panes in Workspace** sends what you type in one pane to every other terminal pane of the workspace, for running the same command on several hosts. **Selected Panes…** starts with the active pane; ⌘-click other panes to add or remove them. Broadcasting panes have an orange border and the status bar reads "Broadcasting to N panes" (click it to stop). Keys and pastes are mirrored; Boo shortcuts are not. Panes running an agent never receive broadcast input, even if one starts later. Broadcast stops when you switch workspaces or only one pane is left in the group.

## Multiple Windows

**Cmd+N** opens a new window. Drag a tab out of the window to tear it off, move a workspace with **Window → Move Workspace to New Window** (or the workspace context menu), or bring everything back with **Window → Merge All Windows**. All windows are restored on next launch.

See [Windows & Splits](/windows-and-splits) for the full guide.

## Quick Terminal

Press **Opt+Space** from any app to drop a terminal down from the top of the screen; press it again to hide it. The shells keep running while it is hidden, and its tabs come back on the next launch.

- **Tabs** — **Cmd+T** opens a tab in the current directory, **Cmd+W** closes it, **Cmd+Opt+1-9** switches. Click a tab to select it, middle-click to close
- **Hides on focus loss** — Clicking another window hides it; turn off **Hide when it loses focus** in Settings → Shortcuts
- **Settings → Shortcuts → Quick Terminal** — change the hotkey (like `` ctrl+` ``, `cmd+shift+t` or `f12`), the height, or turn the hotkey off. **Window → Toggle Quick Terminal** works either way

The quick terminal has no splits. While the hotkey is on, Opt+Space no longer types a non-breaking space in other apps.

## Per-Pane Tabs

Each pane has its own tab bar. Create new terminal tabs with **Cmd+T** (browser tabs with **Cmd+Shift+T**), close with **Cmd+W**, and switch with **Cmd+Opt+1-9** or **Cmd+Shift+1-9**. Closed tabs can be reopened with **Cmd+Opt+Z**. Tabs can also host a browser, text editor, image viewer, or markdown preview — see [Multi-Content Tabs](/multi-content-tabs).

Editor tabs have a status strip (line and column, indentation, encoding, line endings, language), **Save As…** (**Cmd+Shift+S**), autosave, and reload a file that changed on disk. With unsaved edits, Boo asks which version to keep. Set these in **Settings → Editor**.

Smart close order: tab → pane → workspace.

- **Right-click a tab** — Context menu with "Close Tab" (or "Close Workspace" when it's the only tab) and a "Move Tab to Workspace →" submenu listing all other open workspaces.
- **Drag tabs across workspaces** — Drag a tab to a different pane or split zone in the current workspace, or use the workspace pill hover to move it to another workspace entirely. Moving the last tab out of a workspace prompts to close that workspace.
- **Tab groups** — Drag a tab onto the middle of another tab in the same pane, or right-click → **Add to New Group**, to group them under a colored chip named after the folder. Click the chip to collapse the group to the chip alone (it shows the tab count); picking a hidden tab by shortcut or palette opens it again. Right-click a grouped tab to rename, recolor, collapse, remove it from the group or ungroup. Dragging a tab between two tabs of a group adds it; dragging it out removes it. Groups are saved with the session.
- **Vertical tabs** — Settings → Layout → Tab Overflow → **Vertical** moves each pane's tabs into a column on its left (up to 168pt, at most 40% of a narrow pane). Each row shows the title and, under it, the agent status (with its color) or the folder of a running program. Groups get a header row with their chip. Rows scroll with the trackpad; drag to reorder, onto a row's middle to group.
- **Progress bars** — Programs that report progress with OSC 9;4 (cargo, winget, systemd and others) show a thin bar on their tab. The workspace pill shows its furthest-along bar and the Dock icon shows one for all windows. Errors are red, paused is yellow, and an indeterminate report fills the bar. Bars clear when the command finishes or after 15 minutes without a report. Try `printf '\e]9;4;1;50\a'`.

## Command Blocks

Boo's shell integration marks each prompt (OSC 133), so the terminal knows where every command and its output begin and end.

- **Gutter marks** — A thin tick at the left edge of each prompt; red when the command failed
- **Jump** — **Cmd+Up** / **Cmd+Down** scroll to the previous / next prompt
- **Right-click a command** — Copy Command, Copy Output, Re-run, or send its output to an agent
- **Copy Last Output** — **Cmd+Opt+C** copies the output of the last command

## tmux

Run `tmux -CC` (or `tmux -CC attach`) in a Boo terminal, and the tmux session opens as native Boo workspaces: each tmux window becomes a workspace, each tmux pane a Boo pane. Splits and new tabs in those workspaces go through tmux. Turn it off with **Settings → General → Startup → Native tmux windows**; the change applies to terminals opened afterwards.

## Images in the terminal

Programs that use the Kitty graphics protocol show images inline. The file explorer can also show images this way (see [File Explorer](#file-explorer)).

## Quick Select

**Terminal → Quick Select** (**Cmd+Shift+Space**) puts a short label on every URL, file path, git hash, IP address, UUID and hex number on screen. Type a label to copy that text; type it with **Shift** to insert it at the prompt instead. **Delete** removes the last typed letter, and **Esc**, a click or scrolling cancels. Identical matches share a label, and the newest output gets the shortest labels.


## Copy Mode

**Terminal → Copy Mode** (**Cmd+Shift+C**) puts a keyboard cursor on the terminal, starting at the shell cursor. Move it through the whole scrollback with vi keys; the view scrolls along.

| Keys | Action |
| ---- | ------ |
| **h j k l** / arrows | Move one cell or line |
| **w** / **b** / **e** | Next word / previous word / end of word |
| **0** / **^** / **$** | Line start / first non-blank / line end |
| **g** / **G** | Top / bottom of the scrollback |
| **Ctrl+U** / **Ctrl+D**, **Ctrl+B** / **Ctrl+F** | Half page / full page up and down |
| **v** / **V** | Start (or stop) a character / line selection |
| **y** or **Return** | Copy the selection (the cursor's line if none) and leave |
| **Esc** | Clear the selection, then leave |

A number before a motion repeats it (**5j**). **Cmd+C** copies the selection without leaving. Leaving scrolls the view back to where it was.

## Session Recording

**Terminal → Record Session**, or **Start Recording** in a pane's **⋯** corner menu, records the terminal's output as an [asciicast v2](https://docs.asciinema.org/manual/asciicast/v2/) file. **Record All Panes** in the same menu records every terminal pane at once. The tab shows a red dot while recording, and the pane gets a red frame. Choose the item again to stop. Only output and resizes are recorded, never keystrokes. Closing the tab also stops the recording.

**Terminal → Add Recording Marker** (**Cmd+Shift+M**) drops a chapter mark into the running recording; the player can jump between marks.

### Recordings settings

**Settings → Recordings**:

| Setting | Default | Description |
| --- | --- | --- |
| Folder | `~/.boo/recordings` | Where new recordings are saved. **Choose…**, **Reveal**, **Reset** |
| File name | `{date}-{time}-{title}` | Template with `{title}`, `{date}`, `{time}` and `{dir}`. A number is appended when the name is taken |
| Idle time limit | Shorten pauses, 2 s | Pauses longer than this (0.5–60 s) are shortened on playback. Written into each file's header, so other players honour it too |
| Highlight recording panes | On | Red frame around every pane being recorded |
| When a recording stops | Show Toast | **Show Toast**, **Reveal in Finder** or **Nothing** |

The **Library** section lists your recordings. Right-click one to **Play**, **Export Video…**, **Reveal in Finder**, **Copy Path**, **Rename…** or **Move to Trash…**.

### Player

**Terminal → Open Recording…**, or opening any `.cast` file (from Finder or by dropping it on Boo), plays it in a player tab:

| Key | Action |
| --- | --- |
| **Space** or **K** | Play / pause |
| **Left** / **Right** | Back / forward 5 seconds (**Shift**: 1 second) |
| **J** / **L** | Back / forward 10 seconds |
| **[** / **]** | Previous / next marker |
| **-** / **+** | Slower / faster: 0.25×, 0.5×, 1×, 1.5×, 2×, 4× |
| **0** or **Home** | Restart |
| **End** | Jump to the end |
| **1**–**9** | Jump to 10%–90% |

- **Seek** — drag the position slider
- Pauses are shortened to the file's `idle_time_limit`, or to the **Idle time limit** setting if the file has none
- The terminal keeps the recorded size; if the tab is smaller, the edges are cut off

### Export to MP4

**Export Video…** in the player (or the Library's right-click menu) renders the recording to an H.264 MP4 file, faster than real time and with your current theme and terminal font. Pick where to save it (next to the `.cast` file by default); a progress panel shows while it renders, and Finder shows the video when it's done.

## File Explorer

Toggle the sidebar with **Cmd+B**. The explorer shows a live-updating file tree for the current workspace.

- **Local workspaces** — Uses FSEvents for real-time file system watching
- **Remote SSH / Mosh** — Auto-detects SSH-style sessions and reuses shared connections for file listing when possible
- **Remote containers / VMs / devices** — Auto-detects interactive `docker`, `podman`, `nerdctl`, `kubectl`, `oc`, `lxc`, `limactl`, `colima`, `distrobox`, `toolbox`, `vagrant`, and `adb shell` sessions and runs the appropriate listing command for each tool

**Local explorer:**

- **Multi-select** — **Cmd+click** toggles, **Shift+click** / **Shift+↑↓** extends a range
- **Keyboard navigation** — Arrows, **Return** to open, **F2** rename, **Cmd+Delete** to Trash, type-ahead to jump (see [shortcuts](/keyboard-shortcuts#file-explorer))
- **Filter bar** — Fuzzy-filter the whole tree; press **/** to focus it
- **Git status** — VS Code–style badges (M, A, D, R, U, !) on files, rolled up to folders; git-ignored files are dimmed

**File click behavior** (local files):

- **Text/code files** matching the editor file patterns — Built-in editor tab (`textOpenMode`; can also run your terminal editor or open externally)
- **Images** — Image viewer tab (`imageOpenMode`; or inline via the Kitty Graphics Protocol, or the default macOS app)
- **Markdown** — Rendered preview tab (`markdownOpenMode`; or editor, terminal editor, or external app)
- **PDF** — Browser tab (`pdfOpenInBrowser`, on by default)
- **HTML** — Browser tab when `htmlOpenInBrowser` is enabled (off by default)
- **Other files** — Opens with the default macOS app

Configure all of this in **Settings → Plugins → Files**. See [Multi-Content Tabs](/multi-content-tabs#file-opening-settings).

## Sidebar Plugins

The sidebar shows stacked, collapsible panels powered by the [plugin system](/plugins):

- **Files** — Live file tree for the current directory. Supports local (FSEvents) and remote (SSH, Mosh, containers, VMs, and device shells) browsing. Click to open, right-click for context menu.
- **Git** — Branch name, staged/unstaged/untracked files, ahead/behind. Inline stage/unstage buttons. Refresh on file system changes.
- **Agents** — Agent Center for Claude Code, Codex, and OpenCode: open sessions, config, and diffs. **Show Timeline** replays a Claude Code session: prompts, tool calls, tokens, cost and edited files.
- **Snippets** — Saved code snippets with syntax highlighting and quick insertion.
- **Docker** — Running containers with exec, logs, start/stop/restart. Live updates via `docker events` stream. Local sessions only.
- **Bookmarks** — Saved directory shortcuts with per-host namespacing for remote sessions.
- **System** — CPU, memory, disk, network, load, uptime and battery, with quick `df -h` / `top` / `netstat` / `uptime` actions. Optional status bar readouts.
- **Hosts** — The `Host` entries of `~/.ssh/config` (including `Include`d files), with the last connection and the number of open sessions. Click to connect in a new tab, **Opt+click** to connect in a split; right-click to **Go to Session**, **Copy ssh Command** or **Edit in Config**.
- **Notes** — One markdown note per workspace plus a global **Scratch** note, stored in `~/.boo/notes/` and saved as you type. Search all notes, switch between edit and preview, or open a note in an editor tab. **Terminal → Append Selection to Note** adds the selection (or the last command's output) to the workspace's note.
- **Kubernetes** — Off by default; turn it on in **Settings → Plugins**. Pods, workloads, jobs, cronjobs, services and ingresses of the current context and namespace, watched only while their section is expanded. Pods offer **Exec Shell**, **Follow Logs** (or double-click), port-forwarding, **Previous Logs** and **Delete Pod…**; every resource has **Describe**, **View YAML**, **Edit…** and **Copy Name**; deployments, statefulsets and daemonsets add **Scale…** and **Rollout Restart…**, and cronjobs **Run Now…**.
- **Debug** — Live log of plugin lifecycle events and current terminal state, for plugin authors.

Toggle panels via status bar icons or extend with [custom plugins](/plugin-development).

## Agents

Boo tracks coding agents running in your terminals across all windows:

- **Agent inbox** — See which agents are working or waiting; **Cmd+Shift+J** jumps to the next waiting one
- **Agent tasks** — **File → New Agent Task…** starts an agent in its own git worktree
- **Review mode** — **File → Review Changes…** opens a diff tab where you comment on lines and send feedback back (**Cmd+Return**)
- **Handoff** — **Cmd+Opt+Return** sends the terminal selection or last command output to the nearest agent
- **Timeline** — **File → Agent Timeline** replays a session with tokens and estimated cost
- **Remote approve** — Approve or deny waiting agents from the [remote control](/remote-control) page

See [Agents](/agents) for the full guide.

## MCP Server

`Boo --mcp` runs a stdio [MCP](https://modelcontextprotocol.io) server that lets agents read the pane layout, split panes, read or type into other panes, list agents, start agent tasks and open reviews. See [Agents](/agents).

## Git Integration

The status bar shows the current git branch name. Click it to open a branch switcher showing both local and remote branches. The Git sidebar panel shows changed files with inline stage/unstage actions.

## Status Bar

Configurable segments displayed at the bottom of the window:

- **Environment** — Colored dot + label showing the active environment (`local`, `ssh`, `mosh`, `docker`, `kubectl`, and other supported remote types)
- **Git branch** — Current branch name with switcher popup
- **Path** — Current working directory
- **Running process** — Foreground process (zsh, node, vim, etc.)
- **Plugin icons** — Toggle sidebar panels
- **Pane count** — Number of active panes and tabs
- **Clock** — Current time
- **Listening ports** — Ports opened by processes in the workspace's terminals. Click a port to open it in a browser tab or your default browser, copy its URL, go to its pane, or stop the process. Boo notifies you when a new port opens (**Settings → Notifications**)
- **Kube** — `⎈ context/namespace` while the Kubernetes plugin is on; click to switch context or namespace. Red when a [rule](/rules-and-profiles#rules) assigns a profile to that context
- **Sync conflicts** — `⚠ Sync conflict` when a file changed both here and in the [sync folder](/history-and-sync#conflicts)
- **◉ Remote** — while the [Remote Control](/remote-control) server runs

**Settings → Status Bar** shows a preview, toggles the built-in segments (Connection status, Current path, Clock, Pane & tab count, Listening ports) and lists the segments plugins add.

## Rules, Profiles and Shaders

Profiles give a tab its own theme, font, shader, shell and environment; rules pick a profile by host, folder, container, kube context or process, or react to output. See [Rules & Profiles](/rules-and-profiles).

## History and Sync

**Ctrl+R** at a shell prompt searches every command you ran in Boo, across tabs, windows and hosts. Sync keeps your settings, profiles, rules, themes and recipes the same on several Macs through a shared folder. See [History & Sync](/history-and-sync).

## Accessibility

VoiceOver can read the visible terminal text, and the drawn tab bars, workspace pills and their **+** buttons are exposed as buttons you can press. Animations follow **Reduce Motion** in System Settings.

## Security

Secure Keyboard Entry, paste and clipboard-read confirmations, and the owner-only `~/.boo` folder are described in [Security](/security).

## Settings

Open with **Cmd+,**. The sidebar groups the tabs under **Terminal**, **Appearance**, **Apps** and **Plugins**. The search field above it filters tabs by name and by what they contain (try "font", "sync" or "iterm2"); Return opens the first match.

| Tab               | Options |
| ----------------- | ------- |

| **Theme**         | 32 color themes with live preview, custom theme editor (whole UI restyles live while editing) |
| **Appearance**    | Terminal font, font size, cursor style (block/beam/underline/outline), [terminal shader](/rules-and-profiles#shaders); sidebar font and font size |
| **Status Bar**    | Preview, built-in segments (connection, path, clock, pane & tab count, listening ports), plugin segments |
| **Layout**        | Sidebar position (toggle with Cmd+B), workspace bar, tab groups, pane controls, tab overflow mode (scroll/wrap/vertical) |
| **Profiles**      | [Profiles](/rules-and-profiles#profiles) and the default for new tabs |
| **Rules**         | [Rules](/rules-and-profiles#settings--rules) editor, regex tester, `sendText` approvals |
| **Recordings**    | [Recording](#recordings-settings) folder, file names, idle limit, stop action, library |
| **Permissions**   | Code signature, Full Disk Access status, links to privacy settings ([Installation](/installation#permissions)) |
| **Editor**        | Font, editing, display, cursor, terminal links, saving (autosave, format on save, reload on disk change) |
| **Browser**       | Browser tab behavior and history |

## Welcome Window

The first launch of a fresh install opens **Welcome to Boo**: a few starter themes to pick from (with a link to the full list and theme import), and the shortcuts for the command palette, opening a folder, splits, quick select, copy mode and settings. The shortcuts shown follow your rebindings. Reopen it with **Help → Welcome to Boo**; **Help → Boo Documentation** opens these docs.
