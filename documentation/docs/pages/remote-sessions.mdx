# Remote Sessions

When a pane runs a remote shell, Boo notices. The file explorer then lists the remote files, and the status bar and plugins show the remote host and folder.

## Supported Sessions

| Category   | Tools                                                 |
| ---------- | ----------------------------------------------------- |
| SSH        | `ssh`, `mosh`                                         |
| Containers | `docker`, `podman`, `nerdctl`, `kubectl`, `oc`, `lxc` |
| VMs        | `limactl`, `colima`, `vagrant`                        |
| Toolboxes  | `distrobox`, `toolbox`                                |
| Devices    | `adb shell`                                           |

Only interactive sessions count. `docker exec myapp cat /etc/hosts` doesn't switch the pane, and neither does an `ssh` started in the background by a dev server or deploy tool.

## SSH

The file explorer opens its own SSH connection to the host and reuses it for every listing. It needs key-based auth or an SSH agent. Boo reads `SSH_AUTH_SOCK` from your login shell, so agents like 1Password or Secretive work.

If key auth fails, the explorer shows **Connect…**. It opens the connection and asks for a password, passphrase or 2FA code in a dialog.

Coding agents running over `ssh` or `mosh` show up in the [Agent Inbox](/agents#agent-inbox).

## Working Directory

Ghostty only reports the local shell's folder. For remote sessions, Boo reads the folder from the terminal title (`user@host:path`) and from the session's processes.
